# Warehouse Inbox Live & Pharmacist Lender Queue Fixes

- **goal:** Wire Warehouse Inbox with live transport data, implement packing confirmation workflow, direct navigation to transport tracking, and fix Pharmacist Lender Queue lot selection / partial borrow bugs.
- **done:**
  - Branched off `feature/backend-api` to `feature/warehouse-inbox-live`.
  - Replaced mock items in `InboxPage.tsx` with live data fetched via `useTransport()`.
  - Filtered out completed tasks (`RECEIVED` and `CANCELLED`) so items disappear from Inbox once transport is complete.
  - Implemented "ยืนยันจะแพ็ก" packing confirmation button and state persisted in `localStorage`.
  - Added direct link button "ไปที่ขนส่ง {taskNo}" in `InboxPage.tsx` and `InboxDrawer.tsx` navigating to `?page=transport`.
  - Added direct link from Inbound tab (`InboundTable.tsx`) to `?page=transport&dir=in`.
  - Updated `TransportTrackingPage.tsx` to read `?dir=in|out` query parameter on load.
  - Removed mock banner in `App.tsx` for warehouse inbox.
  - Fixed Pharmacist Lender Queue (`LenderQueuePage.tsx`):
    - Replaced hardcoded "รอเราตอบ" badge with dynamic status computation.
    - Updated lot pre-selection to only select lots needed up to requested quantity in FEFO order.
    - Disabled "ให้บางส่วน" button when requested quantity is 1.
  - Fixed white-screen (WSOD) crash on SPA rebuild: added `ErrorBoundary` to `App.tsx` and updated `nginx.conf` with explicit `no-cache` on `index.html` and 404 for missing hashed assets so browsers never execute fallback HTML as JavaScript.
  - Removed decline button and decline KPI card from Warehouse Inbox (WH role only confirms to pack).
  - Wired direct deep-linking from "ไปที่ขนส่ง {taskNo}" so clicking it navigates to Transport Tracking and automatically opens the detail drawer for that specific task.
  - Persisted inbound "รับทราบ" state in `localStorage` (`doorare_wh_in_acked_{hospitalId}`) so acknowledged items remain acknowledged and show "ดูที่ติดตามการขนส่ง" across browser refreshes.
  - Fixed photo attachment preview in Transport drawer (`ShipmentDrawer.tsx`):
    - Previously showed a generic grey box with camera icon and "พร้อมแนบ" / stage label text.
    - Updated `ShipmentDrawer.tsx` to render real thumbnail previews (`<img src="..." />`) with status badges.
    - Added ability to remove pending photos before status submission.
    - Added a lightbox modal overlay so clicking any photo thumbnail expands it to full size.
    - Enabled static file serving for uploads in `backend/src/app.ts` (`/api/v1/uploads`).
    - Added persistent Docker volume `doorare_uploads` to `docker-compose.yml`.
    - Verified build and restarted Docker containers.
  - Fixed photo upload permissions by direction & role in `ShipmentDrawer.tsx`:
    - Previously, "+ เพิ่มรูป" was visible to the receiving warehouse officer even while goods were still at origin or in transit (`WAITING_DISPATCH`, `LOADED`, `IN_TRANSIT`).
    - Restricted photo uploads so receiving warehouse (`out === false`) only has "+ เพิ่มรูป" when status is `ARRIVED` (when inspecting and confirming receipt `RECEIVED`).
    - Allowed sending warehouse (`out === true`) to upload during `WAITING_DISPATCH` (packing/loading confirmation).
    - Updated backend and db schema check constraints to allow `RECEIVED` stage photos.
  - Fixed proxy departure action and photo upload integration (`ProxyStatusPanel.tsx` & `ShipmentDrawer.tsx`):
    - Removed disconnected standalone "+ เพิ่มรูป" button when status is `LOADED` at sender warehouse.
    - Integrated photo upload directly into the expanded "ออกเดินทางแทนคนขับ" (Proxy) section.
    - Warehouse officer can input reason, optionally attach departure photo(s), and submit "ยืนยัน · ออกเดินทางแทนคนขับ" together.
  - Fixed multi-hospital multi-tab test session collision (`AuthContext.tsx` & `apiFetch.ts`):
    - Stored and resolved session tokens via `sessionStorage` with fallback to `localStorage`.
    - Prevents tab 1 (HA) and tab 2 (HC) on `localhost:8080` from overwriting each other's auth token when testing simultaneous sender/receiver workflows.
- **decisions:**
  - Used `localStorage` (`doorare_wh_packed_{taskNo}`) to track packing confirmation state per task locally without requiring extra backend schema changes, while relying on backend `transport_task.status` (`WAITING_DISPATCH`, `LOADED`, `IN_TRANSIT`, `ARRIVED`, `RECEIVED`) for end-to-end task lifecycle.
  - Completed transport tasks (`RECEIVED` or `CANCELLED`) are filtered out from the inbox outbound queue as they no longer need action from warehouse packing.
  - Deep-linked inbound shipments directly to the Inbound tab in Transport Tracking via URL param `dir=in`.
  - Added ErrorBoundary at application root to gracefully catch any unhandled rendering exceptions and provide recovery actions instead of a blank screen.
  - Deep-linked task buttons (`?task=TR-...`) automatically trigger tab direction selection and open the task's detail drawer on Transport Tracking page.
  - Stored and previewed uploaded photo blobs immediately on the client and mapped backend static upload URLs (`/api/v1/uploads/...`) for persisted task event photos.
