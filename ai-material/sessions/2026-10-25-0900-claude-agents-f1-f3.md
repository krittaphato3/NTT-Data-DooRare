# Agents for F1 (lender selection) and F3 (extra items outside kits)

## Goal
- User: use a real LLM for F1 and F3 like F2 does: code gives the bounds, the agent chooses within them, code validates, a human approves, rules are the fallback. Local only (branch feat/agents-f1-f3 from feat/demo-scenarios-f2), not pushed.

## Done
- `backend/src/modules/ai/agents/askJson.ts`: shared "one JSON answer" LLM call (BYOK provider, kill switch / MOCK -> fallback, timeout, one retry telling why). F2 keeps its own tool loop.
- **F1** `borrow/borrow.agent.ts` (task F1_T2_LENDER_SELECTION): picks the first-round lender(s) and quantities, the order of the rest and a message per lender from the ladder the code built. Guards: G-01 schema, G-04 lenders only from the eligible ladder, G-03 qty int 1..lendable, sum <= borrow qty, 1 lender (max_parallel when very urgent), G-05 a message with a number the code did not give is replaced by the template. Wired into `propose` (`borrow.service.ts`): reorders the ladder (`applySelection`), stores `ladder.agent` (summary, picks, priorityAfter), writes `agent_run` (agent BORROW) instead of the old RULES/SKIPPED row. `requestView` returns `proposal.agent` and per-lender `rationale`. Fallback = Si ladder + template. Timeout 60 s (propose is synchronous); `frontend/nginx.conf` /api proxy_read_timeout 90s.
- **F3** `incidents/extras.agent.ts` (task F3_T2_EXTRA_ITEMS): second opinion on items NOT in the kits / rule extras; candidates = drug master with a listing at the hospital, no blood, no controlled; ceiling `max(10, 2 x (red+yellow+green))`; G-01/G-04/G-03; max 8 items. Runs in the background (`startExtrasRun`, in-memory in-flight map, 100 s budget): `POST /incidents/:id/plan/agent-suggestions` -> 202, `GET` -> `{running, latest}`. Nothing is added by the agent: ER presses "+ เพิ่ม" which uses the normal plan edit (`setExtras`).
- Frontend: BorrowDrawer shows the F1 agent card (model, confidence, summary, next-lender order) and the reason on each proposed lender (`borrowLive.agentNoteOf`); ER plan step has `AgentExtrasPanel` (ask, poll, edit qty, add one / all) and the pharmacist incident console shows it read-only (pharmacist may ask).
- Tests (no DB): `tests/borrow.agent.test.ts` (7), `tests/extras.agent.test.ts` (4), allocation agent (6) all pass.

## Verified with the real LLM (nvidia nemotron :free, local Docker DB)
- F1: BR-2026-000611 proposed in ~36 s, status OK, HC chosen with reasons and Thai messages; seen in the UI drawer. One run hit the old 45 s limit and fell back to the Si ladder (recorded FALLBACK) -> limit raised.
- F3: INC-2026-0069 (chemical leak) and a new fire incident: 8 relevant suggestions in ~40 s; "+ เพิ่ม" put Povidone iodine into the plan tables.

## Notes / limits
- The free model is slow and sometimes answers outside the JSON format (then one retry): 35-45 s per call. Summaries are free text and are not number-checked (only the lender messages are).
- Not wired: F1 ladder re-decision after a reject/timeout (later rounds follow the stored order); F3 auto-run after plan creation.
